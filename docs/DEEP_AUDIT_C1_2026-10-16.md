# ИИ Паук v0.38 — глубокий аудит и исправления

**Дата:** 16 октября 2026 г.  
**Артефакт:** `ii-pauk-v0.38-stage-c1-deep-audit-fixed.zip`  
**Тип:** source checkpoint / audit hotfix; не APK и не release build.

## Область аудита

Проверены Android-интеграция локальной GGUF-модели через JNI/llama.cpp, обработка маршрута Local/Yandex, клиент облачного чата, серверный адаптер Яндекс AI Studio, история/память SQLite, контрактные тесты и CI-конфигурация. Отдельно проверена актуальная документация Yandex AI Studio: совместимый endpoint `https://ai.api.cloud.yandex.net/v1/chat/completions`, модельный URI `gpt://<folder>/<model>`, заголовки `Authorization: Api-Key` и `OpenAI-Project` совпадают с официальным примером.

## Найденные проблемы и исправления

### 1. Размер UTF-8 тела облачного чата мог превышать серверный лимит

**Причина:** клиент ограничивал Kotlin-строки по числу символов, а JSON затем кодировался в UTF-8. Кириллица и emoji занимают больше байтов, также добавляется JSON-обвязка. Набор сообщений мог пройти локальные проверки и быть отклонён backend из-за лимита тела.

**Исправление:** клиент сериализует запрос, измеряет реальные UTF-8 байты и удаляет самые старые сообщения, пока payload не укладывается в 14 000 байт. Запас оставлен относительно серверного предела 16 KiB. Последнее сообщение сохраняется; если оно одно превышает предел — запрос отклоняется до отправки. Добавлен Android instrumentation-тест с русским многобайтовым текстом и emoji, проверяющий payload и сохранение последнего вопроса.

### 2. Ошибка транспорта загрязняла историю как реплика ассистента

**Причина:** строка ошибки могла сохраняться в истории под ролью `assistant` и уходить в следующем запросе на облако как будто это ответ модели.

**Исправление:** при сбое отправки пользовательский turn удаляется из истории, а исходный текст возвращается в поле ввода (не затирая новый черновик). Сама ошибка показывается как состояние интерфейса, а не как реплика модели.

### 3. Режим обработки мог измениться между отправкой и началом фоновой работы

**Причина:** рабочий поток считывал выбранный режим позже, чем пользователь отправлял сообщение. Быстрое переключение режима в интерфейсе могло поменять маршрут уже отправленного запроса.

**Исправление:** выбранный режим фиксируется синхронно в момент отправки и передаётся в `respond`. `LOCAL_ONLY` не превращается в облачный запрос лишь из-за последующего изменения выбора; резервное обращение к облаку остаётся только в явно выбранном `LOCAL_THEN_YANDEX`.

### 4. Планировщик просил больше токенов, чем реально поддерживал runtime

**Причина:** `LocalSpiderTaskPlanner` запрашивал 640 токенов, тогда как `SpiderLocalLlmRuntime`/JNI ограничивает генерацию 512. Это незаметно приводило к обрезанию настроек вызывающим кодом.

**Исправление:** запрос планировщика приведён к 512 токенам, совпадающим с ограничением runtime.

### 5. JNI не проверял UTF-8 при преобразовании результата в строку Java

**Причина:** выход генератора может оборваться внутри многобайтового UTF-8 символа; прежний декодер мог превратить неполную/невалидную последовательность в неверный символ. Входная Java-строка также может теоретически содержать непарный UTF-16 surrogate.

**Исправление:** преобразование UTF-8 → UTF-16 валидирует ширину последовательности, продолжения, overlong-кодировки, surrogate code points и границы Unicode. Неверные байты заменяются U+FFFD. Обратное преобразование Java-строки также заменяет непарные surrogates на U+FFFD. Отдельный C++ runtime microtest прошёл ASCII, кириллицу, emoji, обрезанную UTF-8 последовательность, surrogate-кодировку и overlong sequence.

### 6. JNI без проверки использовал результаты инициализации

**Причина:** значения от настройки логитов и инициализации цепочки sampler могли передаваться дальше без проверки `null`/ошибки.

**Исправление:** добавлена обработка ошибок при установке output logits, создании цепочки sampler и её компонентов, а также при получении специального null-token. Ошибки приводят к контролируемому завершению операции и очистке ресурсов, а не к дальнейшему использованию невалидного указателя.

## Проверки, выполненные в этой среде

- Python tests: **87/87 пройдены**, все пять модулей были запущены отдельными командами; общий единый запуск оборвался по таймауту инструмента.
- Python `py_compile`: пройден.
- Local LLM Kotlin source check: пройден против сигнатурных заглушек Android API.
- `HttpSpiderChatClient.kt`: проверка компиляции Kotlin с сигнатурными JSON/model stubs пройдена.
- `local_llm_jni.cpp`: C++ syntax-only check прошёл против **mock `llama.h` и Android logging header** и настоящего JNI header JDK. Отдельный runtime microtest преобразования Unicode в native-коде прошёл. Это не проверка компиляции с настоящим Android NDK и upstream llama.cpp.
- HTML static check в `verify_project.sh`: 130 уникальных ID, встроенный JavaScript синтаксически корректен.
- Android packaged HTML и source HTML совпадают.
- Internal ZIP manifest до этого аудита проверялся на исходном snapshot. Новый `SHA256SUMS.txt` пересчитан после исправлений и проверяется перед упаковкой.

## Проверки, которые не завершены / не выполнялись

- Последний полный `scripts/verify_project.sh` не дошёл до успешного конца: опциональный Chromium/Playwright smoke runner завершился timeout/EPIPE. Поэтому текущий smoke не заявлен как пройденный.
- Agent Core JVM smoke и отдельный typecheck SQLite task repository не завершились в доступное время текущего аудита.
- Настоящий Gradle Android unit/instrumentation test, CMake/NDK build и APK не собраны: Android SDK/Gradle/эмулятор отсутствуют в текущей среде.
- Новый `HttpSpiderChatClientInstrumentedTest` добавлен, но ещё не запускался на устройстве/эмуляторе.
- Нет проверки генерации настоящей GGUF-моделью на Android и нет живого запроса к реальному Yandex AI Studio. Backend tests используют mock provider.
- Не проверен GitHub Actions run. В сеансе репозиторий, ранее доступный через GitHub connector, возвращал состояние пустого репозитория; исходники не загружались туда из этого аудита.

## Остаточные риски / порядок следующей приёмки

1. Загрузить архив в рабочую GitHub-ветку и запустить Android CI; устранить реальные Gradle/CMake/JNI ошибки, если они появятся.
2. Получить успешные `testDebugUnitTest`, `connectedDebugAndroidTest` и `assembleDebug` для `arm64-v8a` и `x86_64`.
3. Проверить на устройстве импорт небольшой GGUF-модели, генерацию, unload/reload, низкую память, неподдерживаемый chat template и работу без сети в `LOCAL_ONLY`.
4. На развернутом HTTPS backend проверить один реальный `/api/chat` и `/api/agent/plan` через Yandex AI Studio, убедиться, что provider key не попадает на клиент и что fallback запускается только в явно выбранном режиме.
5. Завершить визуальный UI smoke на эмуляторе/телефоне и повторить проверку полного проекта после CI.

**Вывод:** исправлены обнаруженные ошибки в байтовом лимите облачного запроса, обработке ошибки чата, фиксации режима маршрутизации, лимите токенов планировщика и обработке ошибок JNI. Это улучшает корректность исходников, но приложение пока не объявляется собранным или проверенным на Android.
