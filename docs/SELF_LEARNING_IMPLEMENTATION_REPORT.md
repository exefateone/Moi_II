# ИИ Паук v0.38 — отчёт внедрения самообучения на истории задач

**Дата контрольной точки:** 16 октября 2026 г.  
**Этап:** C1 — интеллектуальное ядро.  
**Статус:** локальные исходные проверки пройдены; Gradle/Android build, APK, живой запрос к провайдеру и тесты на устройстве не подтверждены.

## Итог исследования

Для этой версии «самообучение» реализовано как адаптация поведения агента через ограниченную эпизодическую память, подтверждённые результаты и явную обратную связь пользователя. Это не обучение или fine-tuning весов базовой модели. История задач остаётся журналом того, что происходило; отдельная память извлекает лишь небольшое число релевантных сигналов для будущего планирования.

Такой дизайн выбран по нескольким причинам:

- **Reflexion** показывает подход с лингвистической обратной связью и эпизодической памятью без обязательного обновления параметров модели.
- **Generative Agents** подчёркивает важность памяти, синтеза опыта и динамического извлечения релевантных воспоминаний.
- **Voyager** демонстрирует ценность повторно используемой библиотеки навыков, но для Паук это будущий этап: сейчас доступен только один read-only инструмент и пока нет основания сохранять исполняемые навыки.
- **LongMemEval** предлагает проверять извлечение, рассуждение между сессиями, временные обновления и отказ от неподтверждённого ответа; эти свойства включены в критерии проверки памяти.
- Материалы по безопасности агентных систем подчёркивают риск prompt injection, раскрытия данных и чрезмерных полномочий. Поэтому память не должна становиться каналом обхода policy или предоставления новых прав.

Источники: [Reflexion, NeurIPS 2023](https://proceedings.neurips.cc/paper_files/paper/2023/hash/1b44b878bb782e6954cd888628510e90-Abstract-Conference.html), [Generative Agents, ACM UIST 2023](https://doi.org/10.1145/3586183.3606763), [Voyager](https://arxiv.org/abs/2305.16291), [LongMemEval, ICLR 2025](https://arxiv.org/abs/2410.10813), [Anthropic: Demystifying evals for AI agents, 9 Jan 2026](https://www.anthropic.com/engineering/demystifying-evals-for-ai-agents), [OWASP Top 10 for LLM Applications](https://owasp.org/www-project-top-10-for-large-language-model-applications/).

## Что реализовано в исходниках

1. **Постоянная эпизодическая память** `FileSpiderLearningMemory`: хранится ограниченный набор до 500 эпизодов. Запись версии 2, чтение и миграция старого формата версии 1; неподдерживаемая будущая схема не должна молча перезаписываться.
2. **Разделение журнала задач и памяти опыта.** История задач остаётся полным прикладным статусом/прогрессом в допустимых границах UI. Память использует минимальные структурированные поля: ограниченные тематические токены, ID разрешённых инструментов, код результата, признак независимой проверки, время, явную оценку пользователя и scope.
3. **Успех не выводится из одной похвалы.** Оценка плана до запуска остаётся `UNKNOWN`; только терминальная задача с подтверждённым статусом может стать `VERIFIED_SUCCESS`. Сбой сохраняется как предупреждающий опыт, а не как образец успеха.
4. **Поиск релевантного опыта** использует совпадение тематических токенов, доверие к типу результата/отзыву и мягкий временной вес. Возраст влияет только на порядок выдачи и не переписывает историческую истинность исхода. Возвращается максимум пять подсказок.
5. **Изоляция рабочих пространств.** Опыт workspace A не передаётся планировщику для workspace B. Глобальный опыт можно повторно использовать только когда сама запись имеет scope `global`. ID области хранится вместо пути файловой системы.
6. **Управление пользователем.** Есть включение/приостановка самообучения, просмотр памяти, забывание отдельного эпизода и удаление всей памяти без удаления истории задач. При паузе новый опыт не записывается, а подсказки памяти не попадают в запрос планировщика; уже сохранённые записи остаются до явного удаления.
7. **Минимизация данных.** Не сохраняются полные prompts, переписки, ответы модели, содержимое файлов, сырой вывод инструментов, секреты или произвольные reflection-тексты. Тематические токены используются только на устройстве для локального retrieval и удаляются из provider-bound JSON. Backend получает только тип эпизода, allowlisted tool IDs, безопасный код ошибки и оценку уверенности.
8. **Безопасность полномочий.** Подсказки памяти являются недоверенными наблюдениями; они не выдают разрешений, не расширяют allowlist инструментов, не отменяют разовое подтверждение пользователя и не позволяют вызвать неподдерживаемую операцию.
9. **Сохранение области задачи.** Рабочая область фиксируется перед планированием. Если пользователь выбирает другую область к моменту подтверждения, выполнение блокируется и требует корректного повторного планирования.

## Что ещё не сделано

- Не меняются параметры/веса базовой модели, не выполняется fine-tuning и нет автономного обучения модели на телефоне.
- Нет embeddings / vector DB / semantic reranker; текущий retrieval намеренно простой, объяснимый и локальный.
- Живой запрос к реальному HTTPS backend/model provider ещё не выполнен. Backend-тесты используют имитацию провайдера; влияние memory context на реальную модель не подтверждено.
- Нет количественного пользовательского benchmark «с памятью против без памяти» на production-модели. Сейчас доказаны контрактные свойства памяти и безопасности, но не измерено фактическое улучшение качества задач.
- Android Gradle-компиляция, официальные Android unit tests, сборка APK и физическое устройство не подтверждены в этом окружении.
- В текущем агенте только один реализованный инструмент — `LIST_WORKSPACE_FILES`; поэтому способность памяти направлять сложные многошаговые операции пока ограничена.

## Выполненные проверки для этой контрольной точки

- Python: **61/61 тестов прошли**.
- Agent Core Kotlin/JVM: **13 групп smoke-сценариев прошли**. Внутри них проверены постоянное хранилище, миграции, область памяти, временное ранжирование, обратная связь, приватность, верификатор файлов, аудит, блокировка повторов и восстановление прерванных задач.
- Spider Media URL policy Kotlin/JVM: **15 утверждений прошли**.
- HTML: **129 уникальных ID**, встроенный JavaScript прошёл `node --check`.
- HTML в Android assets побайтно совпадает с `app-web/ii-pauk.html`.
- Chromium UI smoke: **8 сценариев прошли**, необработанных ошибок страницы не обнаружено.
- Python compileall: пройден.
- Архив и контрольные суммы проверены отдельно при упаковке.

Эти проверки доказывают локальные свойства исходников и платформонезависимых компонентов. Они не заменяют Gradle build, реальный сетевой вызов к провайдеру или QA на Android устройстве.

## Следующий шаг

1. Развернуть и защитить backend с настоящим провайдером модели.
2. Выполнить сквозную задачу и проверить содержимое `learning_context`/результат без утечки тематических токенов.
3. Собрать небольшой повторяемый benchmark на одинаковых задачах с памятью и без неё: полезность, доказанный конечный результат, неподдерживаемые действия, отказ при нехватке контекста, scope leakage и задержка.
4. Только после измерений рассматривать семантический поиск и библиотеку навыков; навыки должны быть типизированными, версионированными и независимо проверяемыми.
5. Параллельно подтвердить Gradle сборку и end-to-end работу на Android.
