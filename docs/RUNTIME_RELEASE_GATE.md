# Spider Native — Linux Runtime Release Gate

## Цель

Не допустить, чтобы несуществующий, чужой или неподтверждённый архив Linux userland отображался как установленный runtime для ИИ Паука.

## Предполагаемая архитектура

- Application ID: `com.iipauk.spider` (пока это scaffold-значение; до релиза его необходимо сверить с реальным Gradle namespace, applicationId и signing identity).
- Runtime bundle: gzip TAR с пользовательским префиксом, согласованным с реализацией инсталлятора.
- ABI указывается явно: `arm64-v8a`, `armeabi-v7a`, `x86_64` или `x86`.
- Манифест закрепляет название файла, байтовый размер, SHA-256, обязательные пути и provenance исходного репозитория/коммита/времени сборки.
- Текущий release gate только проверяет архив. Он **не извлекает** его, не загружает файлы из сети и не меняет устройство.

## Почему нельзя просто перепаковать Termux bootstrap

Пользовательское окружение Android связано с ABI, пакетной идентичностью, путями префикса, нативными библиотеками и механизмом обновления пакетов. Архив, подготовленный для официального приложения Termux, нельзя считать совместимым с `com.iipauk.spider` без отдельной сборки, проверки путей и зависимостей, фиксации лицензий и тестов. Не копируйте официальный bootstrap в чужой application ID как готовое решение.

Перед выбором и реализацией userland следует сверить первоисточники:

- Termux — инструкции для maintainers: https://github.com/termux/termux-packages/wiki/For-maintainers
- Termux — библиотеки для интеграции: https://github.com/termux/termux-app/wiki/Termux-Libraries
- AndroidX WebKit — `WebViewAssetLoader`: https://developer.android.com/reference/androidx/webkit/WebViewAssetLoader

## Что делает валидатор

1. Требует `status: ready` и известную схему манифеста.
2. Требует точный app ID и объявленный ABI.
3. Сверяет имя, размер и SHA-256 архива.
4. Требует provenance с HTTPS-источником, commit hash, UTC timestamp и явным подтверждением проверки кастомной идентичности.
5. Инспектирует gzip TAR без извлечения: отклоняет абсолютные и parent-traversal пути, дубли имён, небезопасные ссылки, специальные записи и архивы за установленными лимитами.
6. Проверяет наличие обязательных путей, по умолчанию `bin/sh`.

Успешная валидация архива сама по себе не доказывает, что он запускается на телефоне. До использования нужны тесты ABI, executable permissions, динамических зависимостей, запуска оболочки, пакетного менеджера, обновления/удаления, квот хранилища и отката после прерывания установки.

## Следующие технические ворота

1. Зафиксировать окончательный applicationId/signing strategy.
2. Выбрать поддерживаемый пакетный стек и сделать отдельную сборку под нужные Android ABI с собственным префиксом.
3. Добавить подписанные/hash-pinned metadata, SBOM и сохранение upstream notices.
4. Реализовать установку во внутренний app-private каталог через временную директорию, проверку пути и атомарное переключение версии; не исполнять команды из недоверенного архива.
5. Добавить отказоустойчивый uninstall/update и проверку свободного места.
6. Подключить API в нативный интерфейс и показывать реальные статусы: `not built`, `ready to install`, `installed`, `failed`, `needs update`.
7. Собрать debug APK в Android Studio и проверить на реальных arm64-устройствах; отдельно проверить отказ разрешений, нехватку места, повреждённый архив, сеть и отмену операции.

## Текущий статус v0.33

Манифест `runtime/linux/linux-runtime-manifest.template.json` намеренно имеет `status: not_built`. Поэтому `scripts/prepare_linux_runtime.sh` ожидаемо завершает проверку кодом 3 (`NOT READY`). Здесь нет installable bundle и нет реализации извлечения/установки на Android.
