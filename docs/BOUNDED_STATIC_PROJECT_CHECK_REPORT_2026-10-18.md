# ИИ Паук v0.39.1 — отчёт по ограниченной статической проверке проекта

**Дата контрольной точки:** 18 октября 2026 г.  
**Версия исходников:** `0.39.1-bounded-static-check` (`versionCode 40`)  
**Тип поставки:** исходный проект ZIP; это не APK и не подтверждённый релиз.

## Что реализовано

Новая операция `CHECK_WORKSPACE_PROJECT` подключена к Agent Broker как типизированный инструмент. Интеграция включает общий контракт и строгий parser, allowlist планировщиков local GGUF, OpenCode Zen и backend Yandex AI Studio, экран явного подтверждения, политику риска, независимый verifier, каталог возможностей и внутреннюю библиотеку обучения.

Проверка только для чтения и работает в выбранном app-private workspace. Она ограничивает обход 8 уровнями вложенности, 2 000 элементами файловой системы, 500 поддерживаемыми текстовыми файлами, 8 МиБ суммарно читаемого содержимого и 64 КиБ на файл. Символические ссылки, служебный маркер workspace, пути с чувствительными именами и файлы с признаками учётных данных пропускаются. Размер и вывод ограничены.

Для `.json` проверяется строгий синтаксис JSON. Для `.xml` и `.svg` используется парсер с включённой secure processing, запретом DTD и отключёнными внешними сущностями. Для остальных поддерживаемых текстовых форматов проверяется только возможность безопасного чтения UTF-8; это **не** проверка грамматики Python, Java/Kotlin, JavaScript/TypeScript, YAML, Gradle или других языков.

После первичного прохода verifier повторяет ограниченную проверку и сравнивает непрозрачное доказательство, в котором учтены метаданные и хеши просмотренных файлов и результаты. При изменении workspace проверка предыдущего результата отклоняется. В журнал и долговременное обучение не помещается текст файлов. Функция не исполняет проектный код, shell, скрипты, тесты, компиляторы, package managers, build tools и не обращается к сети.

## Границы и оставшиеся риски

- Статическая проверка не доказывает корректность всего проекта и не запускает код. Если достигнут лимит обхода, отчёт явно помечает себя как неполный.
- Фильтрация по имени пути и шаблонам учётных данных носит защитный характер, но не гарантирует обнаружения всех возможных секретов.
- Повторный проход подтверждает воспроизводимость bounded scan на момент верификации, но не эквивалентен полноценному тестовому запуску.
- `RUN_PROJECT_TESTS`, произвольный shell, автоматическая установка пакетов, удаление файлов и автономная сборка остаются не реализованы/не подключены.
- Следующий этап — отдельный ограниченный test/check runner с allowlist команд, явным подтверждением пользователя, таймаутом, ограничением вывода и независимой фиксацией exit code и артефактов. Его нельзя выдавать за реализованный до интеграции и тестирования в Android UI.
