# ИИ Паук / Spider Native — глубокий аудит v0.33 и план исправлений v0.34
Дата: 2026-10-12

## Итог
v0.33 — качественный HTML-прототип оболочки с большим количеством функций, но это пока не готовое нативное приложение. Основной риск — разрыв между визуальным интерфейсом и реальными возможностями Android. В интерфейсе уже есть Browser, Terminal, AI, Runtime и плавающий Паук, однако часть функций честно зависит от нативного моста/backend, которых нет в этой HTML-поставке.

## Зафиксированная архитектура
- **Паук — отдельный переносимый виджет-помощник** (плавающий персонаж/быстрый вызов), а не самостоятельная среда выполнения. В дальнейшем его нужно вынести в отдельный Android-компонент с явным разрешением пользователя, управлением видимостью и доступностью.
- **Spider Native** — лёгкий локальный Android shell/PTY, оптимизированный для Android.
- **Spider Linux** — отдельный user-space Linux с пакетами и инструментами; не смешивать с Spider Native.
- **Spider Browser** — самостоятельный нативный браузер на Android WebView/Chromium-стеке с вкладками, историей, закладками, загрузками, безопасной навигацией и реальным доступом к интернету.
- **Spider AI** — отдельный слой модели/агента. Модель предлагает план, локальный исполнитель выполняет только разрешённые действия, результат проверяется; облачные ключи не хранятся в HTML/localStorage.
- **Рабочие пространства** должны со временем быть реальными каталогами в закрытом каталоге приложения и привязываться к PTY cwd, а не только именами в localStorage.

## Сильные стороны
1. Темная мобильная оболочка, заметные основные инструменты, единый drawer/modal-паттерн.
2. HTML escaping применяется в большинстве динамически формируемых карточек/диалогов; чатовый текст добавляется через `textContent`.
3. URL браузера ограничен HTTP/HTTPS; опасные схемы уже отклоняются.
4. Нативный мост использует запросы с идентификаторами и тайм-аутами, а подтверждение внешних действий вынесено отдельно.
5. Runtime-экран прямо сообщает, что HTML не может запускать `/system/bin/sh` и что Linux userland не установлен. Это правильная прозрачность.
6. Локальное хранилище ограничивает объём истории чатов и памяти.

## Критические пробелы (P0 — до заявления о рабочем продукте)
- Нет полного Android Studio/Gradle проекта в этом пакете, подписанного APK и тестов на физическом устройстве.
- Наличие JavaScript-объекта bridge не доказывает, что PTY действительно запускается. Нужен end-to-end тест `open terminal → prompt → command → stdout/stderr → Ctrl-C → close/reopen`.
- Полный Linux userland отсутствует; установщик не должен открываться, пока нет проверенного bundle, подписи/хеша, ABI-матрицы, свободного места, безопасной распаковки и отката обновления.
- Browser iframe-прототип не равен браузеру с гарантированным интернетом: многие сайты запрещают iframe, политика origin запрещает произвольное чтение DOM. Нужен отдельный Android WebView, безопасный navigation delegate, загрузки, сертификатные ошибки без обхода, обработка внешних intent и разрешений.
- Backend/AI: нужен HTTPS, аутентификация, лимиты, тайм-ауты, ограничение размера запроса/ответа, allowlist моделей и серверное хранение секретов. CORS не является аутентификацией.
- Для команд AI нужны минимальные права, allowlist, показ команды/эффекта, подтверждение опасных операций, отмена, аудит и запрет передачи произвольного shell как «безопасного».
- Storage: localStorage — только прототипное хранилище; нужна миграция/экспорт/импорт и обработка повреждённых/частично записанных данных. Для нативной версии предпочтительнее Room/DataStore и атомарные файлы.

## Важные UX/логические улучшения (P1)
- Развести «оболочку приложения» и «виджет Паука»: не дублировать один и тот же доступ к функциям в нескольких постоянно видимых плавающих панелях. Оставить один главный путь навигации и виджет как опциональный быстрый вызов.
- На телефоне длинные модальные экраны должны быть полноэкранными/прокручиваемыми; клавиатура не должна перекрывать адресную строку, ввод команды или кнопки подтверждения.
- Все асинхронные кнопки должны иметь состояния loading/success/error, отмену и восстановление после тайм-аута.
- Добавить единые сообщения об отсутствии native bridge/backend вместо «успешных» пустых действий.
- Доступность: focus trap в модалях, Escape/Back закрывает верхний слой, возврат фокуса, корректные aria-label и контраст; проверить Android TalkBack.
- Для браузера нужны ограничение вкладок/истории, безопасные URL, явное состояние загрузки/ошибки и кнопка «Открыть отдельно».
- Рабочие пространства должны явно помечать статус: «метаданные», «каталог создан», «PTY подключена», «Linux установлен» — не показывать один статус вместо другого.
- Не хранить секреты, токены или приватные команды в browser history, обычном логировании или экспортируемом профиле.

## Упрощение без потери функций
1. Верхний уровень: **Главная / Чат**, **Браузер**, **Терминал**, **AI и инструменты**, **Файлы/рабочие пространства**, **Настройки/диагностика**.
2. Паук — отдельный виджет, который открывает быстрые действия, но не заменяет основную навигацию.
3. Browser, Terminal и Runtime — разные модули. Не объединять браузер и терминал в один экран: у них разные модели безопасности и жизненный цикл.
4. «Linux Runtime» и «Рабочие пространства» можно держать на одной странице диагностики, но состояние установки и список рабочих каталогов визуально разделить.
5. Не добавлять больше декоративных метрик, пока не появились измеряемые реальные статусы.

## Исправления в v0.34
- Версия интерфейса обновлена до v0.34 и схема состояния — до 34.
- Ограничены сохранённые вкладки (12), история каждой вкладки (100 адресов), закладки (60), история терминала (200 записей), запуски AI (100).
- URL с username/password в адресе теперь отклоняется; это снижает риск утечки учётных данных через отображение/историю.
- Сохранено разрешение только HTTP/HTTPS и отказ от опасных схем.
- Уточнены тексты: Паук — будущий отдельный виджет; Browser в HTML — прототип, не заявляется полноценным браузером.
- Полный исходник v0.33 сохранён как legacy для сравнения.

## План разработки по порядку
1. Получить/восстановить полный Android Studio проект и dependency lock/Gradle files.
2. Реализовать Android bridge через WebMessageListener только для доверенного локального origin; валидировать schema, origin, размер сообщения, allowlist методов и лимиты.
3. Подключить PTY и выполнить end-to-end smoke-test на Android.
4. Реализовать реальный каталог workspace и cwd на сессию; не смешивать shell-контекст между workspace.
5. Собрать и проверить Spider Native; отдельно проектировать Spider Linux userland и установщик.
6. Реализовать Spider Browser как нативный WebView с HTTPS, безопасными загрузками, вкладками, историей и загрузками файлов.
7. Добавить AI execution broker: план → diff/команда → подтверждение → выполнение → проверка результата → журнал.
8. Автоматизировать unit, integration, instrumentation, migration, offline, low-storage, process-death, accessibility и security тесты.
9. Только после прохождения release gate — выпускать APK и помечать функции «готово».

## Релизный критерий
Не считать приложение готовым, пока нельзя на реальном Android-устройстве: открыть настоящий PTY, выполнить и отменить команду, создать настоящий каталог workspace и подтвердить cwd, открыть произвольный HTTPS сайт в нативном браузере, загрузить файл с подтверждением, перезапустить приложение без потери данных и проверить, что неподтверждённая AI-команда не выполняется.
