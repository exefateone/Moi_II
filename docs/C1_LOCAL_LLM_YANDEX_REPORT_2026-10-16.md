# ИИ Паук v0.38 — контрольная точка: собственное ядро, локальная LLM и Яндекс AI Studio

**Дата:** 16 октября 2026 г.  
**Статус:** исходники и отдельные компонентные тесты проверены; Android APK, нативная генерация и живой запрос к Яндексу пока не подтверждены.

## Что должно происходить

ИИ Паук остаётся владельцем собственной логики приложения: планирование задач, состояние шагов, разрешения, аудит, независимая проверка результата, история задач и SQLite-память принадлежат приложению. LLM формирует ответ или ограниченный типизированный план, но не может сама выдавать себе полномочия или запускать произвольные команды.

Есть три режима, а не скрытая передача данных:

1. **LOCAL_ONLY** — режим по умолчанию. После сборки JNI-движка и загрузки GGUF Паук генерирует ответы на самом устройстве без сетевого обращения к LLM.
2. **YANDEX_CLOUD** — пользователь явно выбирает облачную модель. Приложение отправляет запрос защищённому backend, backend вызывает Yandex AI Studio.
3. **LOCAL_THEN_YANDEX** — только после явного выбора разрешён резервный вызов облака, если локальная генерация не удалась.

## Что добавлено или поправлено в исходниках

- JNI/CMake-основание локального инференса на upstream `ggml-org/llama.cpp`, закреплённом на версии `v0.6.0`; целевые Android ABI — `arm64-v8a` и `x86_64`, начальная конфигурация CPU-first.
- Нативный экран локальной LLM: импорт пользовательского `.gguf` через системный выбор документов, список моделей, загрузка/выгрузка, локальный чат и выбор маршрута.
- Модель хранится в каталоге приложения `llm`, вне APK и Git. В архив не включены гигабайтные веса модели.
- Импорт проверяет расширение, размер и сигнатуру `GGUF`. Добавлены предварительная оценка свободного места по метаданным источника и повторные проверки при копировании больших файлов.
- Исправлен порядок замены модели: перед заменой файла сначала выгружаются mmap/нативные веса; при неудачном импорте предыдущая модель повторно загружается, если старый файл всё ещё валиден.
- Добавлен backend-адаптер Yandex AI Studio для чата, ограниченного планирования и необязательных embeddings. API key хранится только на сервере; приложение содержит лишь отдельный токен доступа к backend.
- Яндекс-подключение использует фиксированный HTTPS endpoint, `Authorization: Api-Key`, `OpenAI-Project` и отключение серверного логирования запросов через соответствующий заголовок.
- Запросы облачного чата ограничены по размеру и длине истории. В облако не отправляются сырые записи памяти и тематические токены; cloud embeddings отдельно отключены по умолчанию.
- CI workflow подготовлен для контрактных Python-тестов, Gradle unit tests, Android instrumentation на API 35, нативной CMake-сборки и сохранения debug APK. Репозиторий GitHub, доступный в текущем сеансе, пока пуст, поэтому CI не запускался.
- В документации явно определено «самообучение»: память эпизодов SQLite, проверенные результаты, обратная связь и повторное использование релевантных подсказок. Это адаптация поведения, а не онлайн-переобучение весов GGUF.

## Чего честно пока нет

- Не выполнены реальная Android Gradle-сборка, CMake/NDK-компиляция и сборка APK в этой среде.
- Не проверена загрузка настоящего GGUF, генерация текста через llama.cpp и производительность/нагрев/расход RAM на устройстве.
- Не проверены все JNI-символы реальным Android linker на arm64/x86_64.
- Тесты Яндекс API используют mock HTTP provider; нет настроенных пользовательских секретов и не было живого обращения к Yandex AI Studio.
- Репозиторий GitHub пуст и CI ещё не запущен.
- Agent Core по-прежнему исполняет только один зарегистрированный инструмент — `LIST_WORKSPACE_FILES`. Это не произвольный файловый редактор, shell или полный Linux-терминал.

## Серверная конфигурация Яндекса

Добавить секреты на backend-хосте, а не в APK и не в Git:

```dotenv
SPIDER_API_TOKEN=<случайный секрет минимум 24 символа>
PROVIDER_KIND=yandex_ai_studio
YANDEX_API_KEY=<API-ключ сервисного аккаунта>
YANDEX_FOLDER_ID=<идентификатор каталога Yandex Cloud>
YANDEX_MODEL=yandexgpt-5.1
```

На Android нужно указать HTTPS endpoint своего backend, оканчивающийся на `/api/agent/plan`, и отдельный `SPIDER_API_TOKEN`. API key Яндекса в мобильное приложение не вводится. Для настоящего вызова провайдера потребуется предоставить сервисному аккаунту необходимые права Yandex AI Studio и проверить quota/permissions на конкретном каталоге.

## Следующий проверяемый рубеж

1. Загрузить исходники в GitHub, запустить CI и устранить реальные Gradle/CMake/linker ошибки.
2. Получить debug APK только после успешной сборки, установить его на Android-эмулятор и физическое устройство.
3. Импортировать небольшую GGUF-модель, загрузить её и получить короткий локальный ответ без сети; отдельно проверить unload/reload, недостаток RAM/места и неподдерживаемый chat template.
4. Настроить backend secrets и провести живые запросы `/api/chat` и `/api/agent/plan` к Яндексу; убедиться, что ключ провайдера не попадает в APK и логи.
5. Проверить режим `LOCAL_THEN_YANDEX` и подтвердить, что облачный вызов возможен только после явного выбора этого режима.

**Вывод:** требуемая архитектура отражена в исходниках, но исполнение нельзя называть полностью готовым, пока не пройдут реальная Android-сборка, тест с GGUF и live-проверка Yandex API.
